# Kubernetes runner Pod 残留治理设计

日期：2026-09-21；修订：2026-09-22。

状态：按用户确认的核心目标收缩范围，本版取代此前完整生命周期方案。基础清理、执行入口适配、重启补偿及固定四组本地隔离集群验收已完成；未部署线上。进度见[实施清单](../plans/2026-09-22-pod-cleanup-implementation.md)，证据见[验收报告](../../validation/2026-09-22-pod-cleanup.md)，启用方式见[部署说明](../../cleanup-recovery.md)。

## 目标与范围

解决 drone runner kube 因初始化失败、取消/超时、清理失败或 runner 重启而留下 Pod 长期无人处理的问题。

本期目标是：减少 runner 自身故障造成的 Pod 残留，对归属明确且有可靠回收依据的遗留 Pod 自动回收；无法安全处理时保留记录并明确告警。不承诺所有集群异常下都能自动删除 Pod。

| 本期必须完成 | 延后或不包含 |
| --- | --- |
| 初始化部分失败不导致 runner panic | 完整领取协议、claimID、修改 Server Machine |
| 取消、超时及任务退出时及时触发清理 | 阶段终态自动补报及专用 RPC 重试协议 |
| 删除失败可重试，不假报清理成功 | 步骤、Build、下游和通知的状态一致性 |
| 重启后安全补偿，多副本不误删正常任务 | 网络分区、外部强删后的节点级执行状态核验 |
| 不丢失未知创建及晚到资源的回收依据 | 恢复、接管或重跑流水线，日志断线续接 |

资源回收与 Drone 页面状态修复分开：正常任务继续使用既有上报机制；崩溃后页面可能仍显示 pending/running，本期记录可定位的异常，不新增自动修正状态的流程。资源清理完成不以 Server 状态上报成功为条件。

只纳管本版明确标记的新任务资源。升级前的历史 Pod 不自动删除；线上排查保持只读，实际升级或清理另行授权。Kyverno、Drone Server 和集群本身的修复不属于本期。

## 与目标直接相关的现状

1. Setup 在资源创建成功后才初始化 stop，初始化失败后的 Destroy 可能关闭 nil 通道，导致 runner panic。
2. Destroy 的资源删除错误只记日志，仍返回 nil；部分等待可能阻塞，重启后没有旧资源清理流程。
3. runner-go 的正常及 Setup 失败路径先上报阶段，再执行 deferred Destroy；仅修改 Destroy 内部不能确保 Server 故障时及时开始清理。

这些是已核实的实现缺口，尚不等于所有现存残留 Pod 的根因。实施从当前故障的隔离复现开始，只修复与本期验收直接相关的路径。

## 最小实现

### 1. 修复执行期间的停止与清理

- 初始化和销毁允许部分成功，通道关闭及重复销毁安全；容器启动、退出等待和日志读取响应取消。
- 任务正常结束、初始化失败、收到取消、超时或 runner 正常退出时，关闭本任务后续资源创建入口并立即触发清理。
- 对执行收尾入口作最小调整，使清理不等待 Server 日志上传或阶段上报返回；不改变步骤调度、结果分类及 Server 领取协议。进入资源创建前的失败不扩展成阶段恢复功能。
- 清理使用独立、有截止时间的请求；不能被已取消的执行 context 直接取消，也不能无限等待 watcher。优先处理 Pod，附属 Secret 的删除失败不能阻塞 Pod 删除。
- 删除临时失败按有上限的退避重试；权限或准入持续拒绝时保留待处理状态并告警。不能把“发出了删除请求”记为“清理完成”。

### 2. 最小清理记录与重启补偿

重启补偿显式开启，使用 Kubernetes ConfigMap 保存清理记录，放在独立的管理命名空间，不随任务 Pod 或临时命名空间一起消失。不增加数据库。

记录只包含资源回收所需的信息：管理协议版本、runner 池、本任务唯一标识、执行者 Pod UID/容器运行身份/进程会话、资源名称与已知 UID、创建尝试与清理进度、清理原因及最近错误。阶段 ID 仅用于排查关联，不承担 Server 领取归属核验。不得保存脚本、环境变量、Secret 内容或凭据。

启用重启补偿时，在创建第一项任务资源之前建立记录，每个 Create 发送前保存预定名称、唯一归属标记和发送意图；失败时不创建对应资源。记录从资源创建入口开始，不前移到 Accept。运行中保存清理意图失败不能阻塞已经明确应执行的停止尝试。

补偿器启动及运行期间检查本池记录，仅在以下任一事实成立时回收对应资源：

- 执行者已明确结束本次任务、关闭创建入口，并将该任务交给清理流程；runner 进程可以继续服务其他任务。
- 有与记录匹配的可信证据证明旧执行者已经终止，例如同 Pod 内旧容器运行实例的终止事实。

Lease 用于减少多副本重复处理；安全性依赖任务归属、对象 UID 条件、记录版本检查和重复删除安全性。检测到失去处理权后停止新动作；在途请求仍可能完成，后续读取确认结果。

不以年龄、NotReady、Lease 过期、旧 runner Pod 不存在或“本进程没有该任务”单独决定回收。证据不足时保留并告警。只清理本任务创建的 Pod、临时 Secret 和临时命名空间，不删除共享 PVC、共享 Secret 或既有命名空间。

### 3. 未知创建与清理结案

必须区分“确认未发送或未创建”“已创建且取得 UID”“创建结果未知”。先持久化发送意图再发送 Create；发送意图落库后崩溃，即使实际可能尚未发送，也按未知处理。

同一资源不得存在多个未确认的创建请求，受管理资源的 Create 不允许客户端透明重发。结果未知时不重发、不改名绕过、不启动依赖该资源的步骤；补偿器不创建新的执行资源。只有前次明确未创建且任务仍允许执行时，才可记录新的尝试并发送。

符合上述回收条件且创建结果未知时，按预存名称持续进行有截止时间、带退避的查询。发现晚到资源后，核验任务及创建尝试标记、取得 UID，再按 UID 删除；同名但归属不符时保留诊断，不删除。该过程须能跨补偿器重启继续。

NotFound 只能说明本次查询时对象不存在。只有创建尝试已明确未提交，或唯一成功请求已对应到已知 UID，且确认不会再有创建尝试时，才能结合删除后的 NotFound 认定该资源回收完成。未知创建记录不能因重复 NotFound、固定等待或 TTL 而删除。

本任务创建入口已关闭或旧执行者已确认终止、所有创建结果已明确且资源已回收后，清理记录才可结案；仍可能晚到创建的记录继续保留。附属资源失败不妨碍先回收 Pod，但不能提前删除整条回收记录。结案不等待 Drone 阶段状态修复。

### 4. 配置与运行边界

基础崩溃修复、取消响应和删除改进默认生效；重启补偿显式开启，仅支持 runner 随容器退出的 Pod 部署，并取得自身 Pod/容器身份。启用后校验管理命名空间及 Pod、Secret、ConfigMap、Lease 等必要权限；关键条件不满足时拒绝启动新任务资源，不静默降级。集群外运行不承诺跨进程补偿。

沿用现有日志，记录任务资源、执行者、清理原因、尝试次数和错误。区分“删除已请求”“对象已消失”“执行停止未确认”。正常 API/节点条件下按正常删除流程确认对象回收；外部强删或节点失联时，不能仅凭对象消失宣称节点上的容器已停止，应保留异常诊断并告警。本期不建设节点级核验系统。

默认保留 30 秒优雅退出，不强制删除。资源创建或停止证据长期无法确认时，记录可能长期保留；这是明确的异常边界，不能为了让记录归零而误删正常资源。

## 固定验收与交付终点

所有故障注入在本地隔离 Kubernetes 集群进行，线上仅只读。使用必要的单元/组件测试覆盖分支，再做隔离集群回归；不建立通用故障测试平台。验收固定为以下四组：

| 验收项 | 通过标准 |
| --- | --- |
| 1. 当前残留故障回归 | 隔离复现当前故障，记录残留产生点；修复后同一场景不再留下无人处理的 Pod。包含 Secret/Pod 创建失败后销毁，runner 不 panic、重复销毁安全 |
| 2. 清理失败后继续处理 | 删除临时失败后可重试完成；持续拒绝有明确告警和待处理记录。Create 仍在途、补偿先读到 NotFound、随后 Create 成功时，记录未丢失，晚到资源能够被发现和清理 |
| 3. 取消与超时及时回收 | API 和节点正常时，从 runner 收到取消或本地超时触发起，60 秒内确认任务 Pod 消失；Server 不可用、日志上传阻塞、附属 Secret 删除失败或已取消 context 不阻塞 Pod 清理 |
| 4. 重启与双副本安全补偿 | 两个 runner 并行运行，终止其中一个并保留可信终止证据，重启后回收其遗留资源，另一实例正常任务不受影响；验证重复处理、UID 不符、共享资源及证据不足时不误删，补偿重启后仍能处理未知创建记录 |

验收报告分别列出已回收资源和因证据不足/基础设施异常而保留的资源，后者必须说明原因，不能计作回收成功。

完成上述四组验收并通过仓库必要检查后交付。后续审查意见只有能复现或明确说明会导致本期场景中的 Pod 残留、回收记录丢失或正常资源误删，才作为本期阻断项；领取与 Server 状态一致性问题登记后延期，不继续扩大实现范围。
